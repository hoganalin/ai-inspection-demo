# 第二波：均華「智慧製造專案專員」面試準備（決策紀錄）

目標職缺：均華精密 智慧製造專案專員（竹北台元）。用詞依 [CONTEXT.md](../../CONTEXT.md)；產品定位見 [PRODUCT.md](../../PRODUCT.md)。

## 已決定

1. **定位：方法可移轉為主，懂客戶端製程為加分**（2026-10-06）
   均華是封裝設備商（Chip Sorter、Die Bonder 等），職缺改善的是均華**自己的**製造流程。主軸講「痛點 → 有版本號的規範 → 數據驗證 → 預警 → 處置 → 導入計畫」這套方法；另加一頁套用到均華自家工廠的情境（標明為待驗證的假設）。
2. **痛點盤點能力：只做「均華前 30 天盤點計畫」**（2026-10-06）
   不重建過去的盤點經驗。用一頁呈現進廠後的盤點方法；為避免「只是計畫」，必須具體到：訪談對象、要調的數據、選題標準、第 30 天交付物。

3. **工時／產能：做進作品，新增「工時／產能效益」一頁**（2026-10-06，原決定「靠口頭」已撤回：壓力測試發現沒有可用的口頭素材）
   用已量到的人工複判率（改善前 42.5% → 改善後 23.3%）換算：每批 50 顆需人工複判約 21 → 12 顆，乘上單顆複判工時，得出每批工時、每日人力與檢驗站產能；並用 ECRS 重畫檢驗流程。一次補上工時估算、產能、Lean／ECRS 三個缺口。

4. **換算參數：標示假設值＋敏感度分析**（2026-10-06）
   單顆人工複判工時沒有可引用的實際紀錄 → 標「假設值」，並以 15／30／60 秒三種情境呈現結果；每日批數等其他參數同樣標示假設。

5. **簡報：10 頁精簡版，可匯出 PPTX／PDF**（2026-10-06）
   PDCA 結構：① 一句話價值＋線上連結 ② 痛點 ③ 檢驗規範 v1 ④ AI 只辨識、規則判定 ⑤ 一致性分析結果（含變差的漏判率）⑥ 管制圖預警＋異常處置單 ⑦ 工時／產能效益（含敏感度）⑧ 導入計畫（甘特＋RACI）⑨ 均華前 30 天盤點計畫 ⑩ 下一步（規範 v2、導入門檻）。投遞附 PDF，面試現場用同一份。

6. **MES／ERP：簡報第 8 頁（第 11 條調整後為第 7 頁）加 MES 資料流小圖，面試時坦承沒有實際導入經驗**（2026-10-06）
   判定結果欄位（批號、判定、缺陷代碼、規範版本、時間）→ MES；異常 → 異常處置單 → 由人決定是否 Hold（導入計畫範圍已註明不自動 Hold）。標「規格已規劃（導入計畫 4.1／4.2／4.5）、未實作」，並指出批紀錄 CSV 匯出即欄位雛形。

7. **跨部門溝通：由履歷的真實經驗證明，作品不另處理**（2026-10-06）

8. **工時／產能效益的位置：簡報第 7 頁（第 11 條調整後為第 6 頁）＋網站「專案總覽」一個區塊，同一組數字**（2026-10-06）
   放在總覽「量到了什麼」之後；只看線上連結的面試官也看得到。

9. **作者本人兩輪判定：面試前完成**（2026-10-06）
   用 `experiment/results/self-judgment-form.xlsx`：40 張 × 2 輪、打亂順序、隔天進行，兩輪都填完才取消隱藏「標準答案」。表單公式直接算出本人重複性、對標準答案一致率、漏判率、誤判率。完成後把「人 vs AI」一列加進總覽的一致性分析表與簡報第 5 頁，回應「AI 打 AI」的質疑。

10. **時程：一週內投遞**（2026-10-06）

11. **10 頁簡報的比重往「專案推動」調整**（2026-10-06，第二輪 grill）
   原第 3 頁（檢驗規範 v1）與第 4 頁（AI 只回報、規則判定）合併為一頁；騰出的一頁做「怎麼追蹤落地與管風險」（追蹤機制、已觸發風險的處置、追蹤改善成效的 KPI），對應職缺「追蹤各部門執行並落地」與「建立風險預警機制」。總頁數維持 10 頁。

12. **「追蹤與風險」頁只用本專案真實發生的事件當實例**（2026-10-06）
   四件，每件寫成「風險觸發 → 處置 → 追蹤結果」並標真實日期：① API 額度耗盡（R12）→ 先以第 1 次判定完成分析並標「重複性未量測」→ 加值補跑 169 次 → 重複性 77.5%；② 漏判率 37.0%（R01）→ 不進入 ③、提出規範 v2、計畫延後 7 週；③「AI 評 AI」質疑 → 作者本人兩輪判定；④ 預警提早 0 批（R14）→ 不以提早預警宣稱效益。追蹤機制（週會追蹤表欄位、升級規則、風險分級）以樣板呈現並標「規劃」；導入計畫中 2027 年的模擬會議紀錄不放進簡報。跨部門協調的實務經驗仍由履歷證明（第 7 條）。

13. **第 2 頁補上選題理由：四個痛點的共同根因是口頭標準**（2026-10-06）
   一行說明「先把判定依據寫成條文；追溯、預警、複判負荷的改善都建立在它上面」，示範「盤點 → 找根因 → 排優先順序」。不做評分矩陣（分數只能主觀給，反而易被追問）。

14. **小白版簡報同步加「追蹤與風險」頁**（2026-10-06）
   放在「規範 v2」之後，四件真實事件各一行白話（遇到什麼 → 怎麼處理 → 結果），藍框「先止血、照實標示缺什麼、再回頭補量」；「為什麼會這樣」頁補「四個後果同一個根因，所以先改口頭標準」。小白版變 31 頁；NotebookLM 影片不重做。

15. **跑第二輪 PDCA：規範 v2 實際重跑，照實回填**（2026-10-07）
   作者問「為什麼不再跑一輪看改法有沒有效」，決定用 Claude API 重跑（預算上限 US$12，實際 240 次、US$9.55；原估 US$3–4 估太低）。同樣 40 張、3 位評估者、每張 2 次。結果：漏判率 0%、重複性 92.5%、人工複判率 25.8% 達標；評估者間一致率 82.5%、誤判率 7.6% 未達，預警提早未重驗 → Gate ②→③（v2）仍未通過，下一輪 v2.1（框內找實際邊緣、門檻 ±10% 送人工、以 v2 誤差重跑管制圖）。v2 只在實驗流程實作，網站單張判定仍用 v1。簡報「一致性分析」頁改為口述 → v1 → v2 三欄，「下一步」頁改為 v2 結果與 v2.1；追蹤頁加第五件事件（v2 重跑中額度用完兩次，從快取續跑）。小白版 v2 頁移到門檻頁之前、30 秒版本數字改為三組。NotebookLM 影片仍是 v1 時的內容，未重做。

16. **重新定位：對照組改為「人眼＋規範」，問題改為「AI 能否更快、且不比人工差」**（2026-10-08）
   作者指出產線現況不是口述標準，而是有檢驗規範、但由人眼判讀。痛點改為「判讀慢、小缺陷會漏看」；對照用作者本人照規範判的兩輪（79 筆）對 AI＋規則 v2（120 筆）：每顆 34.9 秒 → 8.2 秒、漏判 23.5% → 0%、答對率 70.9% → 75.8%、重複性 87.2% → 92.5%，但誤判 2.3% → 7.6%，結論「AI 更快、更不會放走壞的，但還不能取代人工」。工時改算「AI 先判、人只複判 Warning（25.8%）」：每千顆人工判讀 669 → 173 分鐘（−74%，誤判成本另計）。口述標準條件降為輔助證據（AI 沒有規則時評估者間一致率 57.5%）。痛點來源寫「過去目檢經驗」，不寫公司名（作者自己改了封面）。已改：10 頁面試簡報（封面、痛點、主結果、工時、下一步）、履歷專案成就、兩份練習簡報的 30 秒版本；未改：網站首頁、練習簡報其他頁、手冊、影片。
